## Reproduce local checks

Use the [identity integration instructions](../test/integration/README.md) to start a disposable clean backend with fresh PostgreSQL and the Auth Emulator. Build the web app, run `npm run test:identity`, then stop only the owned test resources. The integration runner keeps fixture credentials inside the disposable container or process memory and disables traces, videos and authenticated screenshots.

On 2 November 2026, all **16 identity integration tests passed** against a clean committed backend image, fresh PostgreSQL and the Authentication Emulator. The [sanitized local report](identity-sessions/local-validation.json) records every case, backend source/image/input digests, full Chromium 156.0.8078.4, browser HTTPS cookie flags and before/after SHA-256 manifests of production source and compiled output. Source and build remained unchanged during the run.

The suite covers author/editor/admin/uninvited access, invitation mismatch/expiry/one-use/replay, open redirects, login/logout CSRF and fixation, trusted credential/header transport, request byte/time limits, cross-author draft privacy, exact backend denial envelopes/tracing, disablement/revocation, actual SDK popup/redirect, memory-only persistence inspected before exchange, account switching and recovery-aware logout. The local HTTPS instance proves browser acceptance of the Secure host-prefixed cookie policy. It does not prove a deployed service or configured Google provider.

The test launcher uses full Chromium. The default headless-shell browser stalled the emulator's child Google loader in this Windows environment; full Chromium completed the same unmodified iframe and loader before the real SDK exchange. No auth responses, credentials or events were substituted, and TLS and application security policies were retained. See the [integration instructions](../test/integration/README.md).

Owned test containers and network were removed after the passing run. Verification preserved all seven saved volumes, unrelated containers/networks and the backend's working files; matching inventory hashes and booleans are in the report. No saved database was used for the tests.

On 2 November 2026, all 136 unit tests, 43 public-reading browser regressions, five SEO checks and 37 durable-editor integration cases passed for the same production source/build. Contract reproducibility, lint, TypeScript, formatting and foundation policy checks passed. The optimized standalone build requires no live backend during compilation. The [current dependency audit](durable-editor/dependency-audit.json) records zero production advisories; moderate development-tool findings remain documented release work.

The [earlier stage-3 security record](identity-sessions/security-validation.json) retains the foundation scan. The [current editor security receipt](durable-editor/security-validation.json) covers the expanded source and browser output, including reviewed synthetic examples and runtime-marker/source-map checks.
